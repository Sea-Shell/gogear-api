Where the spec was silent or ambiguous the implementation chose: (1) a `prerestore` backup of a *dirty* database verifies against the source's own `(version, dirty)` pair, so the restore that ARS-002 section 3 step 7 points to still works after a failed migration; (2) the restore after a failed migration makes no pre-restore backup, following ADR-006 D-7 (ARS-002 step 11 says "section 4 steps 3 to 5", which is off by one against ADR-006 D-6); (3) after that restore the pool is not reopened, because the routine returns the migration error and the process exits; (4) `warnIfForeignKeysOff` runs in `serve` after the routine returns, not inside it; (5) `migration-failed.json` stores versions as strings (`"none"` or a number). No requirement text changed.

- **Creation:** [ADR-006](/docs/architecture/decisions/adr-006-pre-migration-backup-and-restore.md) and [ARS-002](/docs/architecture/spec/ars-002-pre-migration-backup-and-restore.md) realize BR-038 (anchor RD3).
  - The startup routine reads `schema_migrations` with plain SQL before constructing golang-migrate, whose `WithInstance` writes, and finds the latest version from the file source.
  - It snapshots with `VACUUM INTO` on one connection while no listener is open (Recreate, one replica), with a `PRAGMA data_version` check, then verifies the copy (`integrity_check`, version, not dirty) before renaming it.
  - Backups go to `database.backup-dir`, default `backups/` next to the database file; names carry time, kind, schema and app version (embedded at build). Three are kept per kind, and every step is announced as a `gogear-api backup:` stdout line.
  - Restore is one `kubectl set env … GOGEAR_RESTORE_BACKUP=<name>`. It makes a pre-restore backup and an atomic swap, then holds without migrating while the variable is set and the schema is older.
  - A dirty database stops startup with a restore hint. Q-8 and Q-9 are two policy constants, defaulting to refuse and keep.
  - [ARD-001](/docs/architecture/design/ard-001-loadout-planning-and-packing.md) adds task A6b as a precondition of the milestone A merge. [ADR-002](/docs/architecture/decisions/adr-002-zero-touch-release-deploy-and-seeding.md) gets a note: version build argument and diagnostics grep.
