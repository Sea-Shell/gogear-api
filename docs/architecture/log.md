# Architecture change log

## 2026-11-22

- **Creation:** [ADR-001 Realizing category-driven container capability](/docs/architecture/decisions/adr-001-category-driven-container-capability.md) decides how BR-021 and amended BR-020 AC-1 are built: a `top_category_is_container` bool and a three-valued `category_container` field (`"inherit"` removes a sub-category's setting); a read-only derived `gear_is_container`; views `category_container_setting` and `gear_container_capability` as the only place the rule is computed; link triggers that refuse non-capable containers; the capability read inside the immediate link transaction (AC-8); and a new migration 000009 that renames the old per-gear flag to `gearIsContainerLegacy` instead of editing 000008.
- **Creation:** Bundle [index](/docs/architecture/index.md) and this log.
- **Status change:** [ADR-001](/docs/architecture/decisions/adr-001-category-driven-container-capability.md) is now marked implemented: migration 000009, the derived status in every response, the 409 on links and the admin API for the settings are in place. The decisions are unchanged.
- **Creation:** [ADR-002 Zero-touch release, deploy and container seeding](/docs/architecture/decisions/adr-002-zero-touch-release-deploy-and-seeding.md) decides how BR-022 and amended BR-021 AC-5 are built: the nrkno reusable workflow v5.1.6 at `a68fb147`, outputs `released` and `tag` with the guard `needs.release.outputs.released == 'true'`, no `.semrelrc.yml` (the defaults match past releases, T-1), release permissions `contents: write` and `pull-requests: read`, a workflow-wide concurrency group that never cancels a running run, an in-run check of pod digest, restarts and migration version, a local non-publishing rehearsal, the stale `deployment.yaml` pin left as is, and seeding in a new migration 000010 that sets only sub-categories without an explicit setting.
- **Amendment:** [ADR-001](/docs/architecture/decisions/adr-001-category-driven-container-capability.md) OQ-1 closed by P-18 and ADR-002 D-7; its D-5 seeding statement now lives in migration 000010 with an added guard that never overwrites an explicit setting.
- **Status change:** [ADR-002](/docs/architecture/decisions/adr-002-zero-touch-release-deploy-and-seeding.md) is implemented, pending verification of the deploy path (first push-triggered run on `main`): migration 000010 (seeding), the D-8 `gogear-api migrations: version=<N> dirty=<bool>` stdout line, and `release.yaml` with nrkno v5.1.6, `released == 'true'` guards, the concurrency group and the pod verification step. [ADR-001](/docs/architecture/decisions/adr-001-category-driven-container-capability.md) OQ-1 was already recorded as closed by ADR-002 D-7; the only change there is a note in its README-text paragraph that 000010 seeds the settings.
- **Amendment (factual corrections, decisions unchanged):** ADR-002 D-3 now says the PR title decides the bump only for squash merges (a rebase or merge would give `v4.10.0` here because of `feat(db)`; the bump comes from all unreleased commits since the last tag, and `v4.9.3..a8526c3` already holds 3 `fix` commits, so on current `main` any squash title gives at least `v4.9.4`; `chore`/`ci` alone releases nothing only when no other unreleased `fix`/`feat` commit exists). Also noted: the v5 defaults do not release `perf` or `revert`, unlike the old preset (none exist in history). D-9 item 3 and the BR-022 AC-3 and AC-5 rows now say a dry run proves only the computed `tag`, because semrel sets `released = !dryRun`; `released=true` is shown by a local non-dry run against a bare repository and a stub GitHub API.
- **Creation:** [ARD-001](/docs/architecture/design/ard-001-loadout-planning-and-packing.md), [ADR-003](/docs/architecture/decisions/adr-003-loadout-places-registration-items-and-computed-weight.md), [ADR-004](/docs/architecture/decisions/adr-004-expand-contract-release-of-the-loadout-item-contract.md), [ADR-005](/docs/architecture/decisions/adr-005-gear-catalog-states-contributions-and-private-items.md) and [ARS-001](/docs/architecture/spec/ars-001-loadout-loop-schema-and-api.md) realize the loadout planning and packing requirements (BR-023 to BR-036, OC-002 and the 2026-11-22 amendments; handoff question Q-C). The decisions: a `loadout_places` table with Worn created by trigger, items that name the owner's registration and keep a snapshot when it is deleted, ticks and closed state as columns, and an on-your-back `total_weight` computed by views; expand-then-contract release with a temporary gear-only insert path and a later cutover; gear catalog states (`approved`, `private`, `waiting`, `not_approved`) with one visibility predicate, and a merge or replace that only repoints registrations. Private items follow owner choice Q-6 option 1 ahead of its requirement; DC-2's owner condition (keep everything the user provided) is met by construction (ADR-005 D-4). New folders `design/` and `spec/`.
- **Amendment:** [ADR-005](/docs/architecture/decisions/adr-005-gear-catalog-states-contributions-and-private-items.md), [ARS-001](/docs/architecture/spec/ars-001-loadout-loop-schema-and-api.md) and [ARD-001](/docs/architecture/design/ard-001-loadout-planning-and-packing.md) reconciled with BR-037 (private items), the amended OC-002, BR-033 AC-8 and AC-9, P-35, P-36 and the amended frontend design (F8 to F10). Changes: a private item cannot be replaced (409) or deleted, and its only exit is the one-way send to the catalog; an admin's sent private item becomes `waiting`; private items are not in the contribution list; the review routes answer 404 for private items; BR-033 AC-8's 409 is recorded as unreachable by construction, with a revisit trigger; the own-code 409 names the caller's conflicting registration (F10). BR-030 confirmed in milestone A; plan note that BR-023 is partially implemented between milestone A and the cutover. No open markers remain.
- **Amendment (critic review, Loom qa `279ad7b0`):** ARD-001 adds a binding merge rule: each migration reaches `main` in one merge with every handler change that depends on it (BR-022 deploys every merge), with milestone A integrated and merged as one PR (new unit A6) (F1). ARS-001 000011 keeps the `loadout_items` ID sequence across the rebuild, with a required test (F2). `detachedGearId` loses its `ON DELETE SET NULL`, so gear used by legacy or registration-deleted items is refused deletion with 409, as today; snapshot-on-delete was rejected (F3). Legacy items carry no snapshot and read name, maker, category and weight live (F4). An absent bag parent defaults to the closet container only if that bag is still container-capable; otherwise the new bag is top level (F5). Advisories: new trigger `trg_registration_owner_fixed`; down-migration drop order; public-items filter defined for milestone A (items without a current gear row are not listed); ADR-004 records the `gear_weight` 0 → `null` change, and the replay suite seeds a 0-weight gear. Updated: ADR-003 D-3 and D-5, ADR-004 D-1, D-2 and Confirmation, ADR-005 D-4 step 3.
- **Amendment (implementation detail, decisions unchanged):** ADR-002 D-8 now states what the pod verification step actually does: pods in phase `Failed` or `Succeeded` are excluded from the "exactly one pod" count, every `kubectl` call has a 20 s request timeout, the deploy job has `timeout-minutes: 25`, and on failure the step prints bounded diagnostics with the app logs filtered to error-level lines (level, message, error only) so that no usernames or subject IDs reach the public Actions log.
